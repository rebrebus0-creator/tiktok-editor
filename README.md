# tiktok-editor

Локальный монтаж вертикальных роликов (TikTok / Reels / Shorts, 1080×1920)
по размеченному сценарию. Пишешь текст своей речи с тегами в квадратных
скобках — софт читает теги как инструкции и собирает ролик.

**Сценарий = пульт монтажа.** Таймкоды руками проставлять не нужно: теги
привязываются не к секундам, а к словам речи. Софт распознаёт исходное видео
(faster-whisper, таймкоды по словам), сопоставляет текст сценария с реальной
речью и сам находит, на какой секунде произнесена нужная фраза.

> Статус: **этап 0 — каркас**. Работают `check`, `init`, `info`; команда
> `build` проходит по пайплайну и останавливается на первом несобранном
> этапе. Дорожная карта — в конце README.

## Установка (macOS)

```bash
# 1. FFmpeg — ядро монтажа
brew install ffmpeg

# 2. Окружение и зависимости
git clone <репозиторий> tiktok-editor
cd tiktok-editor
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 3. Проверка, что всё на месте
python -m src.main check
```

Или одной командой: `bash install.sh`.

Нужен **Python 3.11+** (используется стандартный `tomllib`).

`check` проверяет: версию Python, наличие ffmpeg/ffprobe, нужные фильтры
FFmpeg (`silencedetect`, `sidechaincompress`, `zoompan`, `subtitles`/libass
и др.), кодеки, установленный faster-whisper, шрифт субтитров.

**Про faster-whisper на Mac:** модель считается на CPU (CTranslate2), поэтому
в конфиге по умолчанию `model = "medium"` и `compute_type = "int8"` — это
компромисс скорость/качество. Точнее, но медленнее: `model = "large-v3"`.
Модель скачивается автоматически при первом запуске (~1.5 ГБ для medium).

**Шрифт субтитров:** положи `.ttf` в `assets/fonts/` и укажи в конфиге
(см. `assets/fonts/README.md`). Без него libass возьмёт системный шрифт.

## Структура проекта

Один ролик = одна папка:

```
projects/<имя_проекта>/
├── raw/            основное видео (говорящая голова) — один файл
├── screencasts/    записи экрана для [ЭКРАН]
├── inserts/        картинки/иконки для [ВСТАВКА]
├── sounds/         звуковые эффекты для [ЗВУК]
├── music/          фоновые треки для [МУЗЫКА]
├── script.txt      размеченный сценарий
├── config.toml     (необязательно) настройки этого ролика
├── .cache/         транскрипт и промежуточные файлы
└── output/         готовый ролик + build.log
```

Создать заготовку: `python -m src.main init my-video`.

## Формат сценария

Пишешь текст своей речи как есть, а инструкции монтажа ставишь в квадратных
скобках рядом с той фразой, к которой они относятся:

```
Привет! Меня зовут Иван, и за сорок секунд я покажу,
как собрать вертикальный ролик, не открывая монтажку. [ЗУМ]

Смотри, вот мой сценарий. [ЭКРАН: demo.mp4]
Я просто пишу текст своей речи и ставлю теги в квадратных скобках —
софт сам находит, на какой секунде я это произнёс. [ЭКРАН СТОП]

Первое правило: [ВСТАВКА: pravilo1.png 3с] снимай одним дублем и не бойся оговорок.
Паузы и запинки программа вырежет сама.

Второе правило: держи паузу перед главной мыслью. [ПАУЗА]
Именно в этой тишине зритель успевает понять, что ты сказал. [ЗВУК: whoosh.mp3]

[МУЗЫКА: lofi.mp3]
Подписывайся, если хочешь так же — по семь роликов в день без монтажёра.
[МУЗЫКА СТОП]
```

Этот пример лежит в `projects/example/script.txt`.

### Теги

| Тег | Что делает |
|---|---|
| `[ЭКРАН: файл.mp4]` | показывает запись экрана вместо говорящей головы; горизонтальный скринкаст вписывается в 1080×1920 (по умолчанию с размытой подложкой) |
| `[ЭКРАН СТОП]` | вернуться к говорящей голове (без него — до конца абзаца) |
| `[ВСТАВКА: файл.png 3с]` | картинка/иконка оверлеем на N секунд (без числа — 3 с из конфига) |
| `[ЗВУК: файл.mp3]` | звуковой эффект в этой точке |
| `[МУЗЫКА: файл.mp3]` | включить фоновую музыку (автоматически тише под голос) |
| `[МУЗЫКА СТОП]` | остановить музыку |
| `[ПАУЗА]` | не вырезать эту тишину — держим паузу для акцента |
| `[ЗУМ]` | плавный наезд на лицо на этом фрагменте |

Правила разметки:

* **Тег действует с того места, где стоит.** Момент ищется по словам речи
  перед тегом («якорь»), поэтому ставь тег сразу после нужной фразы.
* **Длительность** пишется в теге через пробел: `3с`, `2.5s`, `4 сек`.
  Не указана — берётся значение из конфига.
* **Имена файлов** — просто имя из соответствующей папки проекта
  (`demo.mp4` → `screencasts/demo.mp4`). Регистр не важен.
* **Речь может расходиться со сценарием** — импровизация и оговорки
  допустимы, выравнивание нечёткое (`difflib.SequenceMatcher` по
  нормализованному тексту). Если якорь не нашёлся — тег ставится по
  ближайшему совпадению, а в лог пишется предупреждение. Рендер не падает.
* **Имена тегов меняются в конфиге** (`[tags.names]`), можно добавлять
  синонимы: например, `insert = ["ВСТАВКА", "КАРТИНКА"]`.

## Как пользоваться

```bash
python -m src.main init my-video           # создать структуру проекта
# положить видео в projects/my-video/raw/, написать script.txt
python -m src.main info projects/my-video  # проверить: что найдено, как разобрана разметка
python -m src.main build projects/my-video # собрать ролик -> output/my-video.mp4
python -m src.main batch projects          # собрать все проекты разом (5-7 роликов в день)
```

Полезные флаги:

| Флаг | |
|---|---|
| `-v` | подробный лог, включая команды FFmpeg |
| `--raw <файл>` | взять конкретный исходник вместо автопоиска в `raw/` |
| `--no-cache` | распознать речь заново, игнорируя `.cache/transcript.json` |
| `--no-log-file` | не писать `output/build.log` |

Лог каждой сборки сохраняется в `output/build.log`.

## Настройки

Всё настраивается через TOML, код трогать не нужно:

* `config.toml` в корне — общие настройки канала;
* `projects/<имя>/config.toml` — настройки конкретного ролика (перекрывают общие).

Полный список параметров с комментариями — в **`config.example.toml`**:
разрешение и fps, модель распознавания, порог и минимальная длина тишины,
отступы вокруг речи, стиль субтитров (шрифт, размер, цвета, подсветка,
положение), режим вписывания скринкаста, позиция вставок, громкость и
дакинг музыки, параметры зума, имена тегов.

Значения по умолчанию живут в `src/config.py`. Неизвестный параметр в
конфиге не ломает сборку — пишется предупреждение.

## Как это работает внутри

Порядок обработки принципиален: теги привязаны к словам, а после вырезания
пауз все таймкоды съезжают.

1. **Транскрипция** (`transcribe.py`) — faster-whisper с `word_timestamps=True`:
   слова с таймкодами на *исходном* таймлайне. Результат кэшируется.
2. **Парсинг сценария** (`parser.py`) — теги, их аргументы и якорный текст.
3. **Выравнивание** (`aligner.py`) — нечёткое сопоставление текста сценария
   с транскриптом; каждый тег получает таймкод исходника.
4. **Авторез** (`autocut.py`) — `silencedetect` находит паузы; тишина,
   защищённая `[ПАУЗА]`, не вырезается; вокруг речи остаётся padding.
5. **Карта времени** (`timeline.py`) — перевод «исходное время → финальное»
   после вырезания пауз.
6. **Перевод таймкодов** — теги и слова субтитров переносятся на финальный
   таймлайн через эту карту.
7. **Композитинг** (`compositor.py`) — нарезка и склейка (все куски
   приводятся к одному fps/разрешению до `concat`), оверлеи `[ЭКРАН]` и
   `[ВСТАВКА]`, звук (`adelay` + `amix`), музыка с дакингом
   (`sidechaincompress`), `[ЗУМ]`, вшивание караоке-субтитров (libass).
8. **Экспорт** 1080×1920.

Модули:

```
src/
├── transcribe.py    faster-whisper: слова с таймкодами
├── autocut.py       детект тишины и нарезка
├── parser.py        парсер тегов сценария
├── aligner.py       выравнивание сценарий ↔ транскрипт
├── timeline.py      карта перевода времени, события таймлайна
├── subtitles.py     генерация караоке .ass
├── compositor.py    сборка через FFmpeg
├── config.py        настройки
├── project.py       структура проекта и поиск ассетов
├── models.py        общие структуры данных (Word, Tag, Event, ...)
├── ffmpeg_utils.py  запуск FFmpeg/ffprobe
├── errors.py        исключения
├── logging_setup.py логирование
└── main.py          CLI / оркестратор
```

## Дорожная карта

| Этап | Что | Статус |
|---|---|---|
| 0 | Каркас: структура, конфиг, CLI, проверка FFmpeg | готово |
| 1 | Транскрипция + авторез пауз | дальше |
| 2 | Караоке-субтитры (.ass, подсветка слова) | |
| 3 | Парсер тегов + выравнивание → JSON тег→таймкод | |
| 4 | Композитинг: `[ЭКРАН]`, `[ВСТАВКА]`, `[ЗВУК]`, `[МУЗЫКА]` с дакингом | |
| 5 | `[ЗУМ]`, нормализация форматов, экспорт, batch-режим | |

Позже, отдельными фазами после стабильной базы: автоподстановка иконок по
словам речи и GUI-обёртка (перетащил папку → кнопка «Собрать»).
